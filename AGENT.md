# AGENT.md — context for picking this project back up

## What this is

A single-node SeaweedFS deployment on Podman, managed as a systemd quadlet
service (`/etc/containers/systemd/seaweedfs.container`), running as **root**,
with **no reverse proxy**. This is the lab/dev baseline — deliberately kept
simple before layering on hardening.

## State as of this handoff

- Quadlet + entrypoint + install script are done and were sanity-checked in
  conversation, not yet run on target hardware.
- Target host: openSUSE box (not the Fleet-managed Mac — that one has no
  sudo, this needs root).
- Credentials: admin UI + S3 keys are generated by `install.sh` via
  `openssl rand` and stored as Podman secrets — never committed to disk in
  plaintext, never put in `seaweedfs.container` directly.
- Data dir: `/srv/seaweedfs/data`, bind mount, uid 1000 (container's default
  user).

## Deliberately deferred (see README "Known gaps")

Two things were explicitly descoped mid-conversation and should NOT be
silently reintroduced without being asked for:

1. **Caddy reverse proxy** — a full design (shared Podman network, per-service
   subdomain routing, TLS via ACME or internal CA) was worked out earlier but
   is not part of this file set. If asked to add it back, the design pattern
   was: drop `PublishPort=` from `seaweedfs.container`, join both containers
   to a `seaweedfs-net` Podman network, add a `caddy.container` quadlet
   publishing 80/443, `Requires=`/`After=seaweedfs.service`.
2. **Rootless (non-root user) execution** — a full conversion to a dedicated
   user (with `%h`-relative paths, `loginctl enable-linger`, and the
   `net.ipv4.ip_unprivileged_port_start` sysctl for low ports) was also
   worked out but descoped. If revisited, don't forget: rootless Podman
   secrets are per-user, so they'd need to be recreated as that user, not
   reused from root.

## Conventions used here

- Quadlet (`.container` files in `/etc/containers/systemd/`) over hand-rolled
  `ExecStart=podman run` units — survives podman upgrades better.
- Secrets via `podman secret` + `Secret=...,type=env,target=...` in the
  quadlet, never plaintext `Environment=` for credentials.
- Bind mount (`/srv/...`) over named volume for data, so the exact host path
  is explicit and easy to point at a specific disk later if needed.
- `install.sh` is idempotent — re-running it must not clobber existing
  secrets or duplicate work. Preserve this property in any edits.

## If extending this

- Multi-node / replication / erasure coding: out of scope for this file set,
  would need a materially different quadlet (separate master/volume/filer
  services rather than the all-in-one `weed server` command).
- If this ever needs to serve a specific customer engagement with data
  sovereignty constraints (air-gapped, fully local), flag it explicitly —
  that changes image sourcing (no registry pulls), TLS (internal CA only,
  no ACME), and probably argues for the rootless variant too.
